# Task 11 – Final recommendation
Retain the OOP approach, centralise fare policy in a fare-table component, store money as long long integer paise, use enum class for zones, and keep card balance private behind validated canTravel/deduct operations. A fare revision should update one policy table and rerun regression/boundary tests. Limitations: student/senior concession percentages are absent from the question paper and must be supplied by the authority; production software also needs persistence, audit logs, concurrency, security and device/network fault handling. Per-journey calculation is O(1); processing n journeys is O(n).
