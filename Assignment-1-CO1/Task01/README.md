# Task 1 – OOP analysis
Objects: SmartCard (private balance and validated deduction), Passenger (category; concession rate awaits official value), Journey (zone/time/fare), Zone (enum class), FareTable (central policy). Procedural design uses free functions and separate variables; OOP groups state and behaviour. Encapsulation protects balance; abstraction exposes canTravel/deduct; inheritance could represent passenger categories; polymorphism could supply category-specific concession rules once rates are specified. Invariants: nonnegative fare, integer-paise money, accepted journey leaves >=5000 paise, correct peak boundaries, invalid input rejected without changing balance. Both procedural and OOP fare calculations are O(1) time and O(1) per-card space; OOP localises rule changes.
